# Verify & hand off

**Verify:** run the new skill once, for real — use one of the confirmed example invocations, against a real input from the repo (or the most realistic dry run available). Confirm: if it declares required inputs, it asked for missing ones; if it has an interview, the questions came out in recommend-then-confirm shape; the artifact matched the template; and the self-check ran. Fix what didn't — before handing off, not after.

**Hand off:** tell the user, briefly:

1. How to invoke it, with a copy-pasteable example.
2. **The improvement loop** — the part that matters most: the first version is a draft of the process, not the final form. After each real run, notice what chafed — a question that was pointless, a section that always gets edited, an input it should have asked for — and fix the skill in place ("update the skill so that next time it..."). Skills get good by being run, not by being designed. Expect the shape to change: sections you predicted will go unused, and things you didn't predict will keep coming up until you make them real. Kill the former, promote the latter.
